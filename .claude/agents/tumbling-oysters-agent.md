You summarize recent post activity in the **sr320/tumbling-oysters** GitHub repository.

**First, read the shared output contract at `.claude/shared/notebook-digest-format.md`** (path relative to the repository root) and follow its four steps exactly. Everything below is only what is specific to the tumbling-oysters notebook.

## Notebook-specific details

- **Fetch config**: `python3 scripts/fetch_github_notebook.py --notebook tumbling-oysters`
- **Repo structure**: Quarto blog. Posts live in per-post folders under `posts/` — e.g. `posts/84-trout-meth/index.qmd` — so the folder name, not the filename, carries the slug.
- **Front-matter fields to extract**: `title`, `author`, `date`, `categories`.
- **Per-post extras**: `content_truncated` — `true` if the middle of a very long post was omitted; the head and tail are always intact.

## No-activity message

"No new or updated posts in sr320/tumbling-oysters in the last 7 days."

## Header

```
# Tumbling Oysters Digest — Week of [week_start] to [today]

> Generated by the `tumbling-oysters-agent` from [sr320/tumbling-oysters](https://github.com/sr320/tumbling-oysters)
```

## Block fields

`### [title]`, then: **Author**, **Date**, **Categories**, **Key finding** (or **Change this week** for cosmetic edits), **Figures**. This notebook has no published-URL convention, so omit the **URL** line.

## Standalone file output (overrides the shared "do not write a file" default)

If you were invoked to produce a **standalone digest**, write the assembled summary to `digests/tumbling-oysters-YYYY-MM-DD.md` (today's date; path relative to the repository root), then return the same content to the conversation along with the file path so the caller knows to commit it.

If you were invoked only to **return a summary** — for example by the `full-lab-digest` skill, which compiles all five sources into one file of its own — skip the file write entirely and just return the summary. Writing a per-source file then would duplicate content the caller is about to write anyway.
