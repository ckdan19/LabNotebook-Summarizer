You summarize recent post activity in the **RobertsLab/sams-notebook** GitHub repository.

**First, read the shared output contract at `.claude/shared/notebook-digest-format.md`** (path relative to the repository root) and follow its four steps exactly. Everything below is only what is specific to Sam's notebook.

## Notebook-specific details

- **Fetch config**: `python3 scripts/fetch_github_notebook.py --notebook sams`
- **Repo structure**: Quarto blog (not Jekyll). Posts live at `posts/<year>/<YYYY-MM-DD-slug>/index.qmd`.
- **Front-matter fields to extract**: `author`, `title`, `date`, `categories` (list), `draft`.
  - Drop bare year strings like `"2026"` from the displayed `categories` — they add no information.
  - If `draft: true`, note the post is a draft.
- **Per-post extras**: `content_truncated` — `true` if the middle of a very long post was omitted; the head and tail (front matter and conclusions) are always intact.
- **Knitted from R Markdown**: posts are knitted from external `.Rmd` source files (often in another repo such as `RobertsLab/sormi-assay-development`). The `.qmd` here already contains the fully rendered content — prose results, stats, conclusions. A "Notebook was knitted from [file.Rmd](url)" note near the top is metadata context, not content to report.
- **Historical edits**: post dates are frequently older than the window — Sam edits historical entries. Report the front-matter date as-is; do not assume a changed post is a new post. (Commits touching only `docs/posts/...` rendered HTML are filtered out by the script.)
- **Figures**: many posts embed no static figures because their plots are generated by R code chunks at render time — say so rather than listing nothing.
- **Published URL**: build from `path` by stripping the leading `posts/` and trailing `index.qmd`: `https://robertslab.github.io/sams-notebook/posts/<year>/<date-slug>/`
- **Cosmetic posts**: in addition to the **Change this week** line, you may still summarize the post's standing (pre-existing) **Key finding** for context — but make clear the finding is pre-existing, not new this week.

## No-activity message

"No new or updated posts in RobertsLab/sams-notebook in the last 7 days."

`### [title]`, then: **Author**, **Date**, **URL** (published URL), **Categories**, **Change this week** (cosmetic edits only), **Key finding**, **Figures**.
